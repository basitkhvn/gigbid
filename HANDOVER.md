## 2. Switching to local Qwen via Ollama (what to do first)
The repo already supports it (added in the handover commit): provider `ollama` and profile `local_qwen` in `agent/config.yaml`. It uses Ollama's OpenAI-compatible endpoint at `http://localhost:11434/v1` (override with `OLLAMA_BASE_URL`), needs no API key, and `agent/llm.py` strips Qwen3 `<think>...</think>` blocks from output.
```
ollama pull qwen3:14b          # pick a tag that fits VRAM: ~8 GB -> qwen3:8b, ~12-16 GB -> qwen3:14b, 24 GB+ -> qwen3:32b
ollama serve &                 # if not already running
MODEL_PROFILE=local_qwen PYTHONPATH=. .venv/bin/python -c "import agent.llm as l; print(l.complete('writer','Reply JSON {\"ok\":true}','hi',json_mode=True))"
```
If the tag differs, edit the `model:` fields of the `local_qwen` profile in `agent/config.yaml` (all models live in config, never in code). Select a profile with env var `MODEL_PROFILE=local_qwen` (any command) or set `models.profile` in the config.
Qwen3 specifics to check: (a) JSON mode: if `complete_json` returns None often, check raw output; add `/no_think` to prompts or lower `max_tokens` pressure; (b) latency: budgets are p95 <= 60 s/job; local 14B may exceed it, which is fine to report honestly; (c) the Ollama context default is small: for long job posts run with `OLLAMA_CONTEXT_LENGTH=8192` or set `num_ctx`.
`DEEPSEEK_THINKING` is DeepSeek-only and ignored for Ollama. Prices for local models are 0 (add a line in `models.prices` if you want to report a hardware-cost estimate; label it as an estimate).
